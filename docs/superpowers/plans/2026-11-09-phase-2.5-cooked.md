# Phase 2.5: Cooked & Want to Cook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two lists, **Cooked** and **Want to cook**, with a toggle in the library. A ✓ on a wish moves it to Cooked in place, with an optional date cooked.

**Architecture:** A `status` column (`cooked` | `wishlist`) and a `cooked_on date` column on `recipes`. The database refuses a date on a wish. The adapter maps them to `status` and `cookedOn`. `state.js` holds the current list and each list's filters, so they survive opening a recipe and coming back. `CookedDialog.vue` asks for the date.

**Tech Stack:** Vue 3, Vitest + @vue/test-utils, Supabase migrations + pgTAP.

**Spec:** ROADMAP.md Phase 2.5 and Decisions, "Cooked and want to cook". Issue: #15.

## Owner decisions (2026-11-09)

- Recipes saved before this phase become wishes.
- One date per recipe (the last time cooked). A cooking log can come later, in Polish.

## Global Constraints

- Values are exactly `cooked` and `wishlist`. App fields are `status` and `cookedOn` (`'YYYY-MM-DD'` or `null`).
- UI labels: **Cooked** and **Want to cook**.
- All reads and writes go through the storage adapter. No new npm dependency.
- No list counts (owner, 2026-11-09).

## Review Focus

1. **Today in the browser's time zone, not UTC.** Late at night in a UTC-negative zone, `toISOString()` gives tomorrow. Test: `today()` builds the date from the local date parts.
2. **A failed move leaves the wish where it was.** Test: when saving fails, the dialog shows the error and the card stays in Want to cook.
3. **Clearing the date in Edit saves `null`, not `''`.** Postgres refuses `''` for a date. Test: the editor emits `cookedOn: null`.
4. **The filters of the other list don't hide cards.** A tag picked on Cooked must not filter Want to cook. Test: switching lists shows the other list's own, empty filters.
5. **A tag that only exists in one list.** The tag chips come from the current list only. Test: a tag used only on a cooked card isn't offered on Want to cook.

**Interfaces:**
- Produces in `lib/recipes.js`:
  - `emptyRecipe()` adds `status: 'wishlist', cookedOn: null`
  - `today(): string` returns the local date as `YYYY-MM-DD`
  - `formatCookedOn(date: string): string` returns e.g. `Cooked 1 Nov 2026`, using `en-GB` and parsing the date as local
- Produces in `state.js`:
  - `currentList: Ref<'cooked'|'wishlist'>`. It starts as `'wishlist'`, or the last value saved in `localStorage['recipes.list']` (read and write inside try/catch).

  - `markCooked(id, cookedOn: string|null): Promise<recipe>`. It saves `{ ...r, status: 'cooked', cookedOn }` through `saveRecipe`, so a failed save changes nothing.
